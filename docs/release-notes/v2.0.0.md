# OllamaClient v2.0.0 Release Notes

_Released 2026-05-31_

---

## What is OllamaClient?

OllamaClient is a lightweight, idiomatic .NET client library for [Ollama](https://ollama.com) — the local AI model runtime. It gives you a strongly-typed, DI-friendly way to call every Ollama REST endpoint from C# without writing any HTTP plumbing yourself.

---

## What's new in v2.0.0

v2.0.0 is a substantial step forward. The work happened in three waves:

**Phase 1 — Foundation refresh.** We dropped .NET 8 and standardised on .NET 9 and .NET 10, pulled all dependencies up to their current stable releases, modernised the CI pipeline, and set up the tooling hygiene (Dependabot, format checks, pack verification) that future releases depend on.

**Phase 2 — API parity with Ollama.** Four high-demand capabilities were missing from v1.0.0. All four ship in v2.0.0:

- **Tool / function calling.** Pass a list of `Tool` definitions to any chat request. When the model decides to call a function the response carries a `ToolCall` you can dispatch and feed back into the conversation.
- **Structured outputs.** Set `format` to a JSON Schema object (not just the `"json"` string) and the model will return a response that validates against your schema — no post-processing required.
- **Multimodal / vision.** Attach base-64-encoded images to chat messages. Any Ollama-supported vision model (e.g. `llava`, `moondream`) can then reason about the image content alongside the text.
- **Reasoning / thinking models.** Set `think: true` on a request to receive the model's chain-of-thought in a separate `Thinking` field, keeping it cleanly separated from the final answer.

Two smaller gaps were also closed: the new `/api/embed` endpoint (batch embeddings, superseding `/api/embeddings`) and the `/api/version` / `/api/ps` management endpoints.

**Phase 3 — Developer experience.** Every public type now has XML documentation, so IntelliSense surfaces descriptions and parameter hints throughout your IDE. Seven end-to-end sample projects ship with the repository, covering everything from a five-line basic chat to a full retrieval-augmented generation pipeline.

## Migration guide (v1.0.0 → v2.0.0)

### 1. Update your target framework

v2.0.0 requires .NET 9 or .NET 10. .NET 8 is no longer targeted.

```xml
<!-- before -->
<TargetFramework>net8.0</TargetFramework>

<!-- after (choose one) -->
<TargetFramework>net9.0</TargetFramework>
<!-- or -->
<TargetFramework>net10.0</TargetFramework>
```

### 2. Migrate from `/api/embeddings` to `/api/embed`

The legacy `GetEmbeddings` / `GetEmbeddingsAsync` methods are still present but are now marked `[Obsolete]`. They will be removed in a future release. The replacement supports batch embedding and returns a richer response:

```csharp
// before (still works, but triggers a warning)
var response = await client.GetEmbeddingsAsync(new EmbeddingsRequest
{
    Model = "nomic-embed-text",
    Prompt = "Hello world"
});

// after
var response = await client.EmbedAsync(new EmbedRequest
{
    Model = "nomic-embed-text",
    Input = ["Hello world"]          // accepts multiple strings
});
float[] vector = response.Embeddings[0];
```

### 3. Check any code that reads `GenerateRequest.Context`

The `Context` property on `GenerateRequest` and `GenerateResponse` was typed as `string` in v1.0.0, which did not match the Ollama API (it is an array of token integers). It is now `int[]`. If you were storing or passing the context value, update the surrounding code accordingly.

```csharp
// before — would not compile against v2.0.0
string ctx = response.Context;

// after
int[] ctx = response.Context;
```

### 4. Nothing else should break

All other public APIs are additive. Existing `IOllamaHttpClient` call sites, DI registrations, and `OllamaConfiguration` usage compile and run without changes.

## Why try OllamaClient now?

If you haven't used OllamaClient before, here is why v2.0.0 is the right moment to start.

**It covers the full Ollama API.** Every stable endpoint — generate, chat (streaming and non-streaming), tool calling, structured JSON output, vision, embeddings, model management, version, and running-process inspection — is wrapped in a strongly-typed C# method. You get compile-time safety and IntelliSense hints for every parameter.

**It requires almost nothing.** The only runtime dependencies are `Microsoft.Extensions.DependencyInjection.Abstractions` and `Microsoft.Extensions.Http`, both from the standard Microsoft stack. No third-party HTTP libraries, no serialisation frameworks, no surprises in your dependency graph.

**It slots straight into ASP.NET Core or any .NET host.** A single extension method wires the client into the DI container:

```csharp
builder.Services.AddOllamaClient(options =>
{
    options.BaseAddress = new Uri("http://localhost:11434");
});
```

From there, inject `IOllamaHttpClient` or `IStatefulConversationOllamaService` wherever you need it.

**Stateful conversations are first-class.** `StatefulConversationOllamaService` manages the message history for you. Each call appends the new turn and replays the full context — no manual list management required:

```csharp
var chat = serviceProvider.GetRequiredService<IStatefulConversationOllamaService>();
var reply1 = await chat.SendAsync("gemma3", "What is the capital of France?");
var reply2 = await chat.SendAsync("gemma3", "And what is its population?"); // remembers context
```

**Seven samples show you how to get started.** Clone the repository and open any project under `samples/` — each one targets a single feature and has a README that walks through what it demonstrates. The `MiniRag` sample assembles a complete local RAG pipeline in under 80 lines of C#.
